## 규칙 파일

### 1) `.cursorrules`

- 파일: `.cursorrules`
- 포함 섹션:
  - `project`: 프로젝트 목표/참조 문서
  - `code_style`: PEP8, type hints, Google docstring, line length 88
  - `architecture`: ECB 레이어 정의 + 의존 방향(allowed/forbidden)
  - `tdd_rules`: red/green/refactor phase별 규칙
  - `testing`: pytest + AAA, coverage minimum, fixture scope 규칙, naming 규칙
  - `forbidden`: print(), 하드코딩 상수 남발, `except:` 단독 사용 금지
  - `file_structure`: ECB 기반 폴더 트리(주석)
  - `ai_behavior`: 생성 전/중/후 에이전트 행동 규칙

### 2) `.cursor/rules/*.mdc`

- `.cursor/rules/00-project-core.mdc`: 프로젝트 범위/SoT(Report) 고정

## ECB(Entity) 예제: `User`

### 구현 파일

- `entity/user.py`
  - `User`는 `@dataclass(frozen=True, slots=True)`로 불변 지향
  - 검증 규칙:
    - `id`: UUID
    - `username`: 3..32, 정규식 `^[a-zA-Z0-9_]{3,32}$`, 앞/뒤 공백 금지
    - `created_at`: timezone-aware datetime
  - 메서드:
    - `rename(new_username) -> User`: 새 인스턴스를 반환
    - `to_dict() -> dict[str, Any]`: 직렬화

### 테스트 파일 (pytest + AAA)

- `tests/entity/test_user.py`
  - 기본 생성이 유효한 엔티티를 만든다
  - 잘못된 username을 거부한다 (parametrize)
  - timezone-naive `created_at`을 거부한다
  - rename은 동일 id/created_at을 유지하며 새 인스턴스를 만든다
