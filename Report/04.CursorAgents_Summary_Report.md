## 공통 원칙(프로젝트 규칙과의 정합성)

다수 에이전트가 공통으로 강조하는 기준(`.cursorrules`와 정합):
- **ECB 아키텍처**
  - 허용: `boundary -> control -> entity`
  - 금지: `entity -> control|boundary`, `control -> boundary`
  - `entity`는 외부 I/O(파일/콘솔/네트워크/DB) 의존 금지
- **코드 스타일**
  - Python 3.10+, PEP8, line length 88
  - 타입힌트 필수, public API에 Google 스타일 docstring
- **테스트**
  - pytest, AAA(Arrange-Act-Assert)
  - 테스트 약화(삭제/skip/xfail 남용) 금지, TDD 단계(RED/GREEN/REFACTOR) 위반 지양
- **금지 패턴**
  - `print()`, bare `except:`, 매직 넘버/문자열 남발

## 사용 가이드(업무 시나리오별 추천 조합)

- **변경분 품질 게이트(병합 전)**
  - `code-reviewer` → (필요 시) `qa-engineer`로 회귀/실패 모드 보강 제안

- **성능/안정성 개선**
  - `system-engineer`로 병목 가설/측정 방법/개선안 도출 → 구현이 필요하면 `backend-developer` 또는 `frontend-developer`로 이관

- **UI/사용성 개선**
  - `ux-expert`(진단/개선안) → 구현은 `frontend-developer`로 이관

- **AI(LLM) 연동 기능**
  - `ai-integration-expert` 주도(출력 스키마 고정, timeout/retry, 비용/지연 최적화, 보안) + 필요 시 `backend-developer`와 연계

- **복잡한 파이프라인(멀티 에이전트 협업)**
  - `agent-orchestrator`가 리뷰→최적화→UX 개선 흐름을 단계적으로 조율하고, 백업/복원 절차까지 포함해 리스크를 통제
