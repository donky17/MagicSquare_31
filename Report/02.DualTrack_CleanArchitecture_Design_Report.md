## 문서 요약

| 항목 | 값 |
|------|-----|
| 목적 | 레이어 분리 + 계약 기반 테스트 + 리팩토링 훈련 |
| 입력 | `int[4][4]`, `0`=빈칸, 빈칸 **정확히 2개**, 값 ∈ `{0} ∪ {1..16}`, 0 제외 중복 금지 |

| 매직 상수 | **34** (1+…+16)/4 |

# 1) Logic Layer (Domain Layer) 설계

## 1.1 도메인 개념

| 유형 | 이름 | 책임 (SRP) | 비고 |
|------|------|------------|------|
| **Entity** | `Grid4x4` | 4×4 셀 집합 보유, 행·열·대각 접근, 복사본으로 완성 격자 생성 | 불변 권장 |
| **Value Object** | `CellCoordinate` | 1-index `(row,col)` 유효성(1~4) 검증 | 출력·빈칸 식별에 사용 |
| **Value Object** | `EmptyCellPair` | 행 우선 순서의 빈칸 2좌표 `(first, second)` 고정 | 스캔 규칙 단일화 |
| **Value Object** | `MissingNumberPair` | 누락 수 2개 `(smaller, larger)` 정렬 보유 | `s<l` 보장 |
| **Value Object** | `MagicConstant` | 상수 34 캡슐화, 8개 선 합 검사 기준 제공 | VO |
| **Value Object** | `SolutionVector` | `int[6]` 형식·1-index·길이 6 검증 | UI 계약과 동형 |
| **Domain Service** | `PartialGridValidator` | 부분 격자 구조 검증(크기·빈칸 수·범위·중복) | 완성 마방진 아님 |
| **Domain Service** | `EmptyCellLocator` | 행 우선으로 빈칸 2개 좌표 산출 | |
| **Domain Service** | `MissingNumberFinder` | `{1..16} \ present` → 2개, 정렬 | |
| **Domain Service** | `MagicSquareJudge` | **완전 채워진** 격자에 I-1~I-7 판정 | 기존 문제정의 Invariant |
| **Domain Service** | `TwoAssignmentSolver` | 두 배치 시도 후 `SolutionVector` 결정 | 핵심 유스케이스 |
| **Aggregate Root** | `PuzzleSession` (선택) | 부분 격자 → 검증 → 해결 파이프라인 오케스트레이션 | Application 없을 때 대체 |

**의존성 규칙:** Domain은 UI·Data·파일·콘솔에 의존하지 않음.

## 1.2 도메인 불변조건 (Invariants)

### A. 부분 입력 격자 (Domain 진입 전제)

| ID | 불변 조건 | 검증 방법 |
|----|-----------|-----------|
| P-1 | `grid.length == 4` && 각 `grid[r].length == 4` | 차원 검사 |
| P-2 | `0`인 칸의 개수 **== 2** | 카운트 |
| P-3 | `0`이 아닌 값 ∈ {1,…,16} | 범위 검사 |
| P-4 | `0` 제외 값에 **중복 없음** | 집합 크기 == 비영 개수 |
| P-5 | `0` 외 모든 칸이 정수 | 타입 계약(언어 수준) |

### B. 완성 격자 (마방진 판정 시)

| ID | 불변 조건 | 값/규칙 |
|----|-----------|---------|
| I-1 | 4×4, 16칸 | — |
| I-2 | 각 칸 ∈ {1,…,16} | 빈칸 없음 |
| I-3 | 1~16 각 1회 | — |
| I-4 | 4행 합 동일 | |
| I-5 | 4열 합 동일 | |
| I-6 | 주·부대각 합 = 행·열 합 | |
| I-7 | 8개 선 합 = **34** | Magic Constant |

### C. 해 결정 (출력)

| ID | 불변 조건 | 검증 방법 |
|----|-----------|-----------|
| O-1 | `result.length == 6` | 길이 |
| O-2 | `r1,c1,r2,c2 ∈ [1,4]` | 좌표 범위 |
| O-3 | `n1,n2 ∈ [1,16]`, `n1≠n2` | 값 범위 |
| O-4 | `{n1,n2}` = 누락 수 집합 | 집합 일치 |
| O-5 | `(r1,c1)`, `(r2,c2)` = 입력 빈칸 좌표(행 우선) | 좌표 일치 |
| O-6 | 완성 격자가 I-1~I-7 만족 | `MagicSquareJudge` |
| O-7 | `n1`은 1번 빈칸, `n2`는 2번 빈칸에 대응하는 **유일** 배치(아래 규칙) | 시도 규칙 |

**배치 결정 규칙 (결정적):**

`MissingNumberPair(s,l)`, `EmptyCellPair(e1,e2)`일 때:

1. `assign(s→e1, l→e2)` 완성 → 마방진이면 `SolutionVector(e1, s, e2, l)`
2. 그렇지 않으면 `assign(l→e1, s→e2)` 완성 → 마방진이면 `SolutionVector(e1, l, e2, s)`
3. 둘 다 마방진 아님 → **도메인 실패** `NoValidCompletionException`

## 1.4 Domain API (내부 계약)

> 시그니처는 **언어 중립** 표기. 구현 코드 없음.

| API | 입력 | 출력 | 실패 조건 |
|-----|------|------|-----------|
| `validatePartialGrid(grid)` | `int[4][4]` | `void` 또는 `ValidationResult{ok}` | P-1~P-5 위반 시 `InvalidPartialGridException` + `code` |
| `locateEmptyCells(grid)` | P-1~P-5 만족 격자 | `EmptyCellPair` | P-2 위반 |
| `findMissingNumbers(grid)` | P-3,P-4 만족 | `MissingNumberPair` | 누락 개수 ≠ 2 |
| `isMagicSquare(grid)` | 16칸 모두 1~16 | `boolean` | — |
| `fill(grid, coord, value)` | 격자, 좌표, 값 | 새 `Grid4x4` (불변) | coord 빈칸 아님 |
| `tryAssignments(grid, emptyPair, missingPair)` | 위 3 VO | `SolutionVector` | 두 배치 모두 `isMagicSquare==false` |
| `solve(grid)` | `int[4][4]` | `int[6]` | `validatePartialGrid` 실패 또는 `tryAssignments` 실패 |

**`SolutionVector` → `int[6]` 매핑 (고정):**

`[first.row, first.col, nAtFirst, second.row, second.col, nAtSecond]`

**도메인 예외 코드 (고정 enum):**

| Code | 의미 |
|------|------|
| `DIMENSION_INVALID` | P-1 위반 |
| `EMPTY_COUNT_INVALID` | P-2 위반 |
| `VALUE_RANGE_INVALID` | P-3 위반 |
| `DUPLICATE_NONZERO` | P-4 위반 |
| `NO_VALID_COMPLETION` | UC-D05-F1 |

# 2) Screen Layer (UI Layer) 설계 (Boundary Layer)

## 2.1 사용자/호출자 관점 시나리오

| Step | 행위 | 책임 레이어 |
|------|------|-------------|
| 1 | 호출자가 `int[4][4]` 전달 | UI Boundary |
| 2 | **형식·스키마** 검증 (null, jagged array 등) | UI |
| 3 | Domain `solve` 호출 | UI → Domain |
| 4 | 성공 시 `int[6]` 그대로 반환 | UI |
| 5 | 실패 시 **고정 Error schema** 반환 | UI (Domain code → 메시지 매핑) |

**흐름:** `Caller → ScreenBoundary → Domain.solve → int[6] | Error schema`

---

## 2.2 UI 계약 (외부 계약)

### Input schema

| 필드 | 타입 | 제약 | 위반 시 UI code |
|------|------|------|-----------------|
| `grid` | `int[4][4]` | non-null, 각 행 길이 4 | `UI_NULL_GRID`, `UI_JAGGED_ROW` |
| 셀 값 | int | ∈ {0,1..16} | `UI_CELL_RANGE` (Domain 전 단계) |
| 빈칸 | — | 개수 = 2 | `UI_EMPTY_COUNT` (Domain과 중복 시 Domain 우선) |
| 중복 | — | 0 제외 유일 | `UI_DUPLICATE` |

**위임 규칙:** P-1~P-5는 Domain `validatePartialGrid`가 **최종 판정**; UI는 **조기 거부**만 수행(동일 규칙 이중 테스트).

### Output schema (성공)

| 필드 | 타입 | 제약 |
|------|------|------|
| `result` | `int[6]` | `[r1,c1,n1,r2,c2,n2]`, 1-index, O-1~O-5 |

### Error schema

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `success` | boolean | Y | 항상 `false` |
| `errorCode` | string | Y | 아래 표 |
| `message` | string | Y | **고정 문구** (변경 금지) |
| `details` | object | N | `row`, `col`, `value` 등 |

| errorCode | message (고정) |
|-----------|----------------|
| `UI_NULL_GRID` | `입력 격자가 null입니다.` |
| `UI_JAGGED_ROW` | `모든 행의 길이는 4여야 합니다.` |
| `UI_CELL_RANGE` | `셀 값은 0 또는 1~16이어야 합니다.` |
| `DIMENSION_INVALID` | `격자는 4행 4열이어야 합니다.` |
| `EMPTY_COUNT_INVALID` | `빈칸(0)은 정확히 2개여야 합니다.` |
| `VALUE_RANGE_INVALID` | `0이 아닌 값은 1~16이어야 합니다.` |
| `DUPLICATE_NONZERO` | `0을 제외한 값은 중복될 수 없습니다.` |
| `NO_VALID_COMPLETION` | `주어진 빈칸에 유효한 마방진 완성이 없습니다.` |

| 오류 시뮬레이션 | Map 조작 | 파일 없음/깨진 JSON |
| 교체 용이성 | 동일 인터페이스 | 동일 인터페이스 |

**추천:** **A (InMemory)를 1차 구현·테스트**, **B (JSON 파일)를 2차 통합** — RED→GREEN 속도와 Data 테스트 단순화 우선; File은 통합 테스트 2건만 추가.
