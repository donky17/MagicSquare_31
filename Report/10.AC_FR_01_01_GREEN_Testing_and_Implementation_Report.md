## 2. 커밋 전략 (통합 2커밋)

### 2.1 전략 선정

| 방식 | 커밋 수 | 채택 |
|------|---------|------|
| 세분화 | 4 (None + `[]` + jagged + 3×4) | — |
| **통합** | **2 (None + size 일괄)** | **✅** |

**선정 이유:** B-T02~B-T04는 동일 `INVALID_SIZE` 응답·동일 검증 함수로 일괄 GREEN 가능. 커밋 2-B(메타 테스트)는 테스트 설계 수정이므로 동일 커밋 또는 직후 커밋으로 묶는다.

### 2.2 커밋 1 — `grid=None` (B-T01) · DEF-001 ✅

| 항목 | 내용 |
|------|------|
| 구현 | `if grid is None:` → `FailureResult(code="INVALID_SIZE", message="Grid must be 4x4.")` |
| 격리 | `_resolve` 미호출 |
| 통과 테스트 | #1~9 (`TestNormalFailureReturn` 5 + None isolation/message 4) |
| git 커밋 | 대기 (체크리스트 미체크) |

### 2.3 커밋 2 — size 일괄 (B-T02~B-T04) + 메타 (DEF-002~008) · RED

#### 2-A. Boundary (DEF-002~004)

| ID | 입력 | 구현 방향 |
|----|------|-----------|
| B-T02 | `grid = []` | `len(grid) == 0` 조기 거부 |
| B-T03 | `grid = [[]] * 4` | `any(len(row) != 4 for row in grid)` |
| B-T04 | `3×4` | `len(grid) != 4` |

공통 응답: `FailureResult(code="INVALID_SIZE", message="Grid must be 4x4.")`  
대상 테스트: #10~20 (11건)

| # | 테스트 | 수정 방향 |
|---|--------|-----------|
| 21 | `test_module_has_no_4x4_valid_grid_test_function` | 기능 테스트 함수명만 AST 검사 |
| 22 | `test_module_has_no_forbidden_ac_fr_01_02_to_05_test_names` | docstring/상수 오탐 제외 |
