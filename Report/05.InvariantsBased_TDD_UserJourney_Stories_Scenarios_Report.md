## 목적

4x4 Magic Square(2빈칸 완성) 문제를 사용해 **불변식(Invariant) 기반 설계 사고**를 훈련하기 위한 학습/명세 산출물을 정리한다.

- 본 문서는 **구현 코드/테스트 코드 없이** Epic→Journey→Story→Scenario→Verification까지의 연결을 고정한다.
- 다음 단계(Level 6+)에서 RED 테스트와 구현 Task로 안전하게 분해될 수 있도록 **계약(Contract)과 불변식 중심**으로 작성한다.

## Level 1 — Epic (Business Goal)

- **Epic Title**: 불변식 기반 사고 훈련 시스템 구축 (4x4 Magic Square TDD Practice)
- **Business Goal**: 불변식 중심 설계 → 계약 고정 → Dual-Track TDD → 리팩토링 → 회귀 보호의 학습 루프를 구축
- **Learning Goal**: Concept → Invariant → Contract → Test 추적성, Boundary/Domain 분리, 계약 불변 리팩토링
- **Success Criteria(핵심)**:
  - Domain Logic 테스트 커버리지 95%+
  - Boundary 입력 검증 계약 테스트 100% 통과
  - 매직 넘버 금지(명명된 상수), 정답 하드코딩 금지
  - 주요 Invariant는 최소 1개 이상 테스트로 추적 가능
  - 리팩토링 후에도 외부 입력/출력 계약 불변

---

## Level 2 — User Journey (5 Stages)

1. **Problem Recognition**: “정답 구현”이 아니라 “불변식 기반 설계 훈련”으로 재프레이밍
2. **Contract Definition**: Input/Output/Error 계약을 구현보다 먼저 고정
3. **Domain Separation**: BlankFinder / MissingNumberFinder / MagicSquareValidator / Solver 책임 분리
4. **Dual-Track TDD Progress**: Boundary RED vs Domain RED를 분리하여 진행
5. **Regression Protection**: 정상/오류/조합 실패/포맷 회귀를 계약/불변식에 연결해 보호
