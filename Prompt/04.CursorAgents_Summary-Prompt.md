## 공통 규칙(프로젝트 기준)

다수 에이전트가 공통으로 강조하는 프로젝트 규칙:
- **ECB 아키텍처**: `boundary -> control -> entity` (역방향 의존 금지)
- **Python 3.10+**, **PEP8**, **line length 88**
- **타입힌트 필수**, **Google 스타일 docstring(공개 API)**
- **pytest + AAA**, TDD 단계(RED/GREEN/REFACTOR) 준수
- 금지: **`print()`**, **bare `except:`**, **매직 상수 남발**

## 에이전트별 사용 가이드(언제 호출할까)

- **`agent-orchestrator`**
  - 다단계 흐름(리뷰 → 최적화 → UX 개선)처럼 “여러 에이전트를 연계”해야 할 때
  - 안전 작업(백업/복원, 파괴적 Git 명령 주의)까지 포함한 워크플로우 관리가 필요할 때

- **`code-reviewer`**
  - PR/변경분을 병합하기 전, 버그/규칙 위반/테스트 공백/성능 이슈를 구조적으로 점검할 때
  - Blocking vs Non-blocking 구분이 필요한 리뷰 산출물이 필요할 때

- **`system-engineer`**
  - 성능(시간/메모리)/안정성/운영성 관점에서 병목 후보를 “측정 기반”으로 진단하고 싶을 때
  - 복잡도 개선(중복 계산 제거, 자료구조 선택 등)을 제안받고 싶을 때

- **`qa-engineer`**
  - 실패 모드(에러 처리) 품질, 경계값/비정상 입력에 대한 회귀 방지 테스트를 강화하고 싶을 때
  - 버그 리포트(재현 절차/최소 입력/기대 vs 실제)가 필요할 때

- **`backend-developer`**
  - API 계약/데이터 처리 파이프라인/외부 연동(타임아웃·재시도·오류 변환) 설계·구현이 필요할 때

- **`frontend-developer`**
  - UI 구조/상태 흐름/반응형/접근성(A11y)/프런트 성능을 개선하고 싶을 때

- **`ux-expert`**
  - 에러 메시지/상태 안내/버튼 배치/일관성 등 사용성 관점에서 개선점을 찾고 싶을 때

- **`ai-integration-expert`**
  - OpenRouter 기반 LLM 호출을 설계·구현하고, 프롬프트/출력 스키마/안전·비용·지연 최적화까지 다루고 싶을 때

- **`product-manager`**
  - 기능 정의/우선순위/마일스톤/PRD 같은 “기획 산출물”이 필요할 때
